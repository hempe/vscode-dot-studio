**Goal:** Visual Studio's Code Cleanup (file, folder, project, solution, and the open editor) and Sync Namespaces (project, folder), documented with pages and GIFs.

**Architecture:** Both features are menu entries registered in `src/core/contextMenus.ts` (single source; run `npm run generate:menus`). Code Cleanup runs `dotnet format` in three steps in a progress notification. Sync Namespaces asks the C# extension's Roslyn server for the code action "Change namespace to '...'" on every C# file of the node and applies it (the server also fixes the references in other files). Pure functions (argument building, file selection) carry the tests; the VS Code glue stays thin.

**Standing user rule (applies to every task below):** any change the end user sees or needs to know about updates its docs page in the SAME task (and the GIF scene in `scripts/screenshots/capture.sh` + `docs/images/*.gif` when the visuals are new or changed; if a GIF cannot be recorded in this environment, say so plainly in the report, commit the scene, and never commit a README/docs link to a missing image). `docs/context-menus.md` is generated; `docs/keyboard-shortcuts.md` must list every key binding and `docs/settings.md` every setting of `package.json` (tests check both). Untested-in-VS-Code checks go to `docs/manual-testing.md` UNTICKED. Do not touch `docs/roadmap.md` (the controller does it).

**Project rules:** see CLAUDE.md (strict TS with noUnusedLocals/noUnusedParameters, webview code must not import vscode/Node, judge `npm run build:dev` by exit code, commit straight to master with the trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`, never push, never `git add` docs/superpowers).

**Verified facts (from probes on 2026-10-20; re-verify what your task relies on):**
- `dotnet format` (SDK 10) handles .sln, .slnx and project files, ~2-3 s on a tiny project. `dotnet format whitespace <target> --include <file-or-folder>` fixes indentation/spacing/braces but does NOT sort usings. `dotnet format style <target> --diagnostics IDE0005 --severity <x>` removes unused usings; IDE0005 is not reported above `hidden/info` by default, so the step needs `--severity info` unless `.editorconfig` raises it. `dotnet format style <target> --severity warn` applies the style fixes the `.editorconfig` sets at warning/error. Options: `--include`, `--exclude`, `--no-restore`, `--verify-no-changes`, `--report <dir>` (JSON report), `-v`.
- The Roslyn server of `muhammad-sammy.csharp` 2.160.9 offers, on the namespace line of a file whose namespace does not match its folder (needs `dotnet_diagnostic.IDE0130.severity = warning` and `dotnet_style_namespace_match_folder = true` in `.editorconfig`), the code action "Change namespace to 'Demo.Sub.Deep'"; resolved it edits the declaration and adds/fixes references in other files. No "Fix All" is offered for it. It is NOT offered if IDE0130 does not report.
- A throwaway LSP probe client lives in /tmp/lsp-probe (probe*.js, may be gone) if you want to repeat checks against the real server.

**Files:** create `src/services/codeCleanup/cleanupSteps.ts`, `src/services/codeCleanup/codeCleanup.ts`; tests `src/test/unit/services/codeCleanup/cleanupSteps.test.ts` (+ a mocked-vscode test for the runner if practical, following `src/test/unit/services/pack.test.ts` or `runTask` tests for how child processes and vscode are mocked).

- [ ] **Step 1: Failing tests for `cleanupSteps`.** Signature: `cleanupSteps(target: { kind: 'solution' | 'project' | 'folder' | 'file'; path: string; projectPath?: string }, severity: 'info' | 'warn' | 'error'): { cwd: string; steps: Array<{ label: string; args: string[] }> }`. Behaviour:
  - solution/project: the target is the solution/project file, no `--include`, cwd its directory.
  - folder/file: the target is the OWNING project file (`projectPath`, required for these kinds), cwd the project's directory, `--include <path relative to the project dir, forward slashes>` (a folder gets a trailing `/`).
  - three steps in this order: `whitespace` (label "Formatting"), `style --diagnostics IDE0005 --severity info` (label "Removing unused usings"), `style --severity <severity>` (label "Applying code style fixes"); every step starts with `format`, then the subcommand, then the target, then the options.
  - tests for each target kind, relative path with subfolders, a path with spaces, and the severity values.
- [ ] **Step 2: implement `cleanupSteps.ts`; run its tests; commit** "Code Cleanup: the dotnet format steps".
- [ ] **Step 3: verify the steps on a real throwaway project** under /tmp (a messy file with unused usings and bad whitespace plus an `.editorconfig` WITHOUT an IDE0005 severity): run each step's args with `dotnet`, confirm whitespace is fixed and the unused usings are removed, and that a style rule set to `warning` in `.editorconfig` is applied by the third step while one set to `suggestion` is not at `warn`. If any claim in "Verified facts" is wrong, fix the steps and say so in your report. Also check what `--report <dir>` writes (JSON shape: which files changed) because the summary uses it; and whether a failing step (exit code != 0, e.g. build/restore error) prints something useful.

### Task 3: Sync Namespaces core

**Files:** create `src/services/namespaceSync/syncPlan.ts`, `src/services/namespaceSync/namespaceSync.ts`; tests under `src/test/unit/services/namespaceSync/`.

- [ ] **Step 1: pure `candidateFiles(rootDir, listFiles)`** (or similar: take the list of paths and filter): `.cs` files under the node, excluding `bin/`, `obj/`, `node_modules`, generated files (`*.g.cs`, `*.designer.cs` case-insensitive, `*.AssemblyInfo.cs`), sorted by path; uses `shouldSkipDirectory`/`isExcluded` from `core/constants.ts` if they fit. - [ ] **Step 2: `syncNamespaces(nodePath, deps)` loop** with injected dependencies for testability (`deps.codeActions(uri, range) => Promise<Action[]>`, `deps.apply(edit) => Promise<boolean>`, `deps.namespaceLine(file) => Promise<number | undefined>` etc.), and a default `deps` bound to VS Code: `vscode.commands.executeCommand('vscode.executeCodeActionProvider', uri, range, undefined, <itemResolveCount so edits are resolved>)`, `vscode.workspace.applyEdit`, saving each changed document. Behaviour per file: find the namespace line (`NamespaceService.parseNamespaceFromFile` exists in `src/services/namespaceService.ts`; reuse it; file-scoped and block-scoped both), request code actions for that line's range, pick the action titled /^Change namespace to '/ (not "Fix All"), resolve it if it has no `edit` (`codeAction/resolve` through the item resolve count, or `vscode.commands.executeCommand` as the API allows: verify), apply its edit, save. Files are processed ONE AT A TIME, in order (each edit changes the documents the next sees); after an applied action the file is re-checked once more (it must no longer offer the action) to catch a no-op. Result object: `{ changed: string[]; unchanged: number; failed: Array<{ file: string; reason: string }> }`. A file without a namespace, or where the server offers no such action, counts as unchanged (already matching). Test the loop with fakes: changes, no action, apply failure, cancellation (a `CancellationToken` stops after the current file), duplicates.
