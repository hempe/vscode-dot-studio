**Verified facts (2026-10-20):**
- Visual Studio 2022 17.11+ saves multi-project launch profiles in a JSON file with the extension `.slnLaunch` next to the solution (same base name); "Share Profile" ticked = the file meant for source control, unticked = a user-specific file (probably `<name>.slnLaunch.user`: verify against any real example or say it is unverified). Format (Microsoft Learn): a JSON array of profiles `[{ "Name": "Feature Profile", "Projects": [{ "Path": "src\\Web\\Web.csproj", "Action": "Start" }, { "Path": "src\\Data\\Data.csproj", "Action": "StartWithoutDebugging" }] }]`; actions are `Start`, `StartWithoutDebugging`, `None`; the dialog also has a per-project "debug target" (launch profile; the JSON key is unverified: preserve unknown keys when writing and treat `DebugTarget` as the launch profile name only as best effort); launch order = array order. Visual Studio's dialog: Solution Property Pages > Configure Startup Projects: radio "Single startup project" / "Multiple startup projects", project list with Action, up/down arrows, Share Profile.
- `dotnet dev-certs https --check` exits 0 when a valid certificate exists; `--check --trust` exits 7 when none is trusted (on this Linux machine: valid but untrusted, the exact case to handle); `--check-trust-machine-readable` prints JSON `[{ Thumbprint, ..., IsHttpsDevelopmentCertificate, TrustLevel: "None" | "Partial" | "Full" }]`; `--trust` (without --check) trusts, creating one if needed; trusting on Linux is partial (browsers/OpenSSL stores differ by distro), on Windows/macOS it opens the system trust prompt.
- `dotnet watch run --project P --launch-profile X --non-interactive` sets `DOTNET_WATCH=1` (and `DOTNET_WATCH_ITERATION`) on the child processes it launches; the child restarts on rude edits and after each restart the process id changes.
- The C# extension used here is `muhammad-sammy.csharp` (netcoredbg); it cannot apply Edit-and-Continue itself, so "Hot Reload with F5" in the Visual Studio sense is not available; `dotnet watch` applies deltas through its own startup hook.
- Existing code to read first: `src/services/debugConfigService.ts` (the "Startup" launch.json configuration, `launchConfiguration`, `startProject(projectPath, noDebug)`, `startStartupProject`, `.NET Framework` Mono branch, launch profiles), `src/services/dotnetTaskProvider.ts` + `src/services/runTask.ts`, `src/webview/providers/ConfigurationManagerPanel.ts` and `src/webview/configuration-view/` (an editor tab + React UI to model new tabs on), `docs/run-and-debug.md` (user docs of the area), `src/core/contextMenus.ts` (menus), `src/extension.ts` (commands).

### Task 5: HTTPS development certificate

Trust runs `dotnet dev-certs https --trust` in a visible terminal (Windows/macOS prompt by themselves); on Linux show what `--trust` can and cannot do (the output explains) and a link to the .NET docs.
