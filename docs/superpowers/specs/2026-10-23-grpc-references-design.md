# Phase 21: gRPC references in Connected Services

Covers the gRPC item of Phase 21 in `docs/roadmap.md`. The OpenAPI item is dropped (see "Not planned" below).

## Goal

Add, update and remove gRPC references (`.proto` files) from the Solution Explorer, like Visual Studio's "Add Connected Service > gRPC" and the `dotnet-grpc` tool, without that tool being installed.

## Behaviour (decided)

- **Add:** right-click a project or its Connected Services folder > **Add Service Reference...**. The command first asks for the type: WCF Web Service (the existing SOAP flow, unchanged) or gRPC. gRPC then asks for the source (a `.proto` file picker, or a URL), then for what to generate: Client, Server or Both. The default is Client, and Both for web projects (`Microsoft.NET.Sdk.Web`), as `dotnet-grpc` does.
- **In the tree:** gRPC references are listed in the project's Connected Services folder, one node per `.proto`, whether or not the folder holds anything else. Context menu: **Update** (URL references only: download again, compare content hashes, replace the local file only if it differs) and **Remove** (removes the `<Protobuf>` item; the `.proto` file is never deleted, as with `dotnet-grpc remove`).
- **Project file:** a text edit through `ProjectFileEditor` adds `<Protobuf Include="Protos\x.proto" GrpcServices="Client" />`; a local file outside the project directory gets a `Link="Protos\x.proto"` element (what `dotnet-grpc` writes). A second reference to the same file is refused with a message.
- **Packages:** Client: `Grpc.Net.Client`, `Google.Protobuf`, `Grpc.Tools` (`PrivateAssets="All"`); web projects: `Grpc.AspNetCore` (which brings the rest); installed through the Central Package Management aware code of Phase 20 (`changePackageVersions`), so a solution with `Directory.Packages.props` gets `PackageVersion` entries instead of versions in the project file. Packages already referenced are left alone.
- **URL source:** the file is downloaded into `Protos/` (created if needed) under the URL's file name; Update uses the URL remembered in the project (an attribute `SourceUrl="..."` on the `<Protobuf>` item, which `dotnet-grpc` also writes).
- **Not generated by us:** the C# classes come from `Grpc.Tools` at build time.

## Design

- `src/services/grpc/protobufReferences.ts` (no `vscode` import): list the `Protobuf` items of a project (from the project items evaluation of Phase 19, `ProjectItemsService`, which must also read `Protobuf` items with their `GrpcServices`, `Link`, `SourceUrl`; check `ITEM_TYPES` in `projectItems.ts`), pure text edits to add and remove one, the package set per project kind, and the download-and-compare for Update.
- `src/services/grpc/grpcReferenceService.ts`: the host side (pickers, confirmations as native modals like the other services, progress, errors), registered next to `serviceReferenceService.ts`.
- `src/core/contextMenus.ts`: commands `addGrpcReference` (reached through the type picker of `addServiceReference`, not a menu entry of its own), `updateGrpcReference`, `removeGrpcReference`, a node type `folder.grpcReference` (or the existing `folder.serviceReference` family, decided in the plan after reading the tree code), then `npm run generate:menus`.
- `src/services/solutionTreeService.ts`: gRPC reference nodes under Connected Services.
- Node ids stay opaque to the webview (`nodeIdService`).

## Testing

- Pure tests of the edits (formatting kept, CRLF, Link, duplicates, escaping of file names).
- Real-MSBuild tests: after the edit the project's `Protobuf` items evaluate as expected, `dotnet build` of a scratch client project with `Grpc.Tools` generates the client classes (skipped without `dotnet` and without network for the package restore, like the other real tests; the restore may need the NuGet cache).
- Tests of the host service with an injected downloader, picker and runner.
- A tree test for the reference nodes.

## Docs

`docs/connected-services.md`: a gRPC section (add, what is written, update, remove, the packages). A scene `gif-grpc` in `scripts/screenshots/capture.sh` and `docs/images/grpc.gif`. `docs/manual-testing.md` unticked entries, the roadmap item moved to `docs/history.md` when done.

## Not planned

- **OpenAPI clients:** Microsoft deprecated the `<OpenApiReference>` item and `dotnet openapi` in .NET 10 (the package `Microsoft.Extensions.ApiDescription.Client`), and recommends the generators' own tools (NSwag, Kiota, OpenAPI Generator); Kiota has a VS Code extension of its own. To be built if someone opens an issue.
- Scaffolding a gRPC service (Phase 30).
